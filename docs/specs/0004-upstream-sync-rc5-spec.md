# Спецификация 0004: Синхронизация Soft-Fork с апстримным релизом движка dsh-v0.2.1-rc.5 (`upstream-sync-rc5`)

- **Статус триажа:** `ready-for-agent`
- **Категория:** `Development` / `Feature`
- **Фича:** `upstream-sync-rc5`
- **Базовый тег апстрима:** `dsh-v0.2.1-rc.4` → `dsh-v0.2.1-rc.5`
- **Целевая версия продукта:** `1.0.0` → `1.0.1`

## Problem Statement

Апстрим-репозиторий выпустил релиз `dsh-v0.2.1-rc.5`, зафиксированный регулярным воркфлоу `Strata Upstream Release Radar` (запуск `41241879883`) и зарегистрированный в GitHub Issue #8. Текущая база `StrataHarness 1.0.0` остаётся на теге `dsh-v0.2.1-rc.4`. Для поддержания форка в актуальном состоянии необходимо выполнить регламентную синхронизацию кодовой базы с сохранением четырёх фундаментальных инвариантов `Soft-Fork`:

1. **Отставание от актуальных правок апстрима:** апстрим включил кастомизацию слотов рендеринга блока рассуждений модели (PR #7484, `ReasoningRow` и `ReasoningContent` в `packages/client/ui-chat`) и версионный бамп зависимостей ядра до `0.2.1-rc.5`. Без синхронизации продукт не получает эти улучшения и исправления.
2. **Риск деградации инвариантов изоляции `StrataHarness`:** прямое или автоматическое слияние без контроля способно случайно вернуть пути к `~/.deepseek`, сбросить кастомную схему `strata://` или appId `com.nikl.strataharness`, восстановить активные воркфлоу апстрима в `.github/workflows/` (вместо архивного каталога `.github/upstream-workflows/`) или перезаписать специфичные для форка скрипты `strata:*` в корневом `package.json`.
3. **Риск нарушения 100%-го паритета русской локализации:** любые изменения структуры интерфейса апстрима могут потребовать адаптации словарей в `@strata/locale-ru` и нативной оболочке Electron. Без прогона специализированных гейтов паритета новые элементы рискуют отображаться на английском языке.

## Solution

Выполнить управляемую процедуру синхронизации Soft-Fork согласно регламенту `docs/strata/fork-maintenance.md`:

1. **Изолированная ветка синхронизации:** скрипт `strata:prepare-upstream-sync` создаёт ветку `sync/dsh-v0.2.1-rc.5` и проверяет чистоту рабочего дерева.
2. **Слияние без автокоммита:** выполнение `git merge --no-commit --no-ff dsh-v0.2.1-rc.5` с ручной ревизией индекса и разрешением пересечений в файлах `strata(override)` (`package.json`, `apps/cli/package.json`).
3. **Защита четырёх инвариантов Soft-Fork:**
   - Строгая изоляция `.github/workflows/` (только `strata-*.yml`).
   - Сохранение трёхуровневой изоляции путей, appId и схем протоколов.
   - Обновление версий пакетов ядра `@deepseek-ai/dsh-*` до `0.2.1-rc.5`.
   - Полный паритет русской локализации через запуск `russian-localization-parity.spec.ts`.
4. **Полный сквозной прогон квалификационных гейтов:** валидация через `audit-overrides`, тест паритета локализации, `constraints`, `build`, а также smoke-тесты сборки десктопа `check:package` и `test:updates:local` с нормализацией `PATH` для `tar.exe` на Windows.
5. **Двухконтурное версионирование и интеграция:** обновление базового тега апстрима до `dsh-v0.2.1-rc.5` и инкремент версии продукта `StrataHarness` до `1.0.1` (`patch`) через `pnpm run strata:version patch`, локальная интеграция ветки синхронизации в `main` и закрытие Issue #8.

## User Stories

1. Как пользователь `StrataHarness`, я хочу получать актуальные исправления ядра и интерфейса апстрима (включая улучшенный рендеринг блоков рассуждений модели), чтобы приложение работало стабильно и использовало последние наработки платформы.
2. Как пользователь, я хочу, чтобы после обновления апстрима интерфейс продукта сохранял 100% русскоязычную среду без пропущенных строк или внезапных английских надписей в блоке рассуждений чата.
3. Как пользователь десктопного приложения, я хочу, чтобы приложение сохраняло полную изоляцию пользовательских данных в каталоге `~/.strataharness`, схему вызовов `strata://` и отдельный профиль ОС, не конфликтуя с оригинальным DeepSeek Harness.
4. Как мейнтейнер проекта, я хочу, чтобы при слиянии апстрима в `.github/workflows/` не появились нежелательные воркфлоу или автообновления Dependabot, нарушающие CI форка.
5. Как мейнтейнер проекта, я хочу, чтобы версии всех пакетов ядра автоматически поднялись до `0.2.1-rc.5`, а скрипты управления форком `strata:*` в корневом `package.json` остались невредимыми.
6. Как разработчик, я хочу, чтобы все локальные сборочные гейты, включая компиляцию артефактов TypeScript, проверку архитектурных зависимостей (`constraints`) и аудит переопределений (`strata:audit-overrides`), завершились успешно до фиксации коммита слияния.
7. Как разработчик, работающий в среде Windows, я хочу, чтобы десктопный гейт упаковки `check:package` корректно использовал системный `System32\tar.exe`, предотвращая ложные сбои путей GNU tar.
8. Как мейнтейнер проекта, я хочу, чтобы манифест `strata-product.json` корректно зафиксировал `upstreamBaseTag: "dsh-v0.2.1-rc.5"` и новую патч-версию `productVersion: "1.0.1"`, а открытый радаром Issue #8 был закрыт со ссылкой на выполненную синхронизацию.

## Implementation Decisions

- **Использование штатного тулинга форка (`fork-ops.ts`):** подготовка ветки и версионирование осуществляются строго через команды `pnpm run strata:prepare-upstream-sync dsh-v0.2.1-rc.5` и `pnpm run strata:version patch -- --upstream-base dsh-v0.2.1-rc.5`. Это исключает рассинхронизацию между манифестом `strata-product.json` и версиями в пакетах форка.
- **Приоритет версий пакетов апстрима:** при разрешении пересечений в `package.json` и `apps/cli/package.json` версии `@deepseek-ai/dsh-*` принимаются равными `0.2.1-rc.5`, в то время как конфигурация скриптов `strata:*`, локализация `@strata/locale-ru` и настройки форка сохраняются.
- **Контроль паритета локализации в рамках текущей сессии:** если апстримный PR #7484 внёс новые строковые литералы или слоты, требующие локализации, недостающие ключи добавляются в `packages/strata/locale-ru/` до коммита слияния.
- **Нормализация PATH на Windows:** при локальном вызове `check:package` на Windows переменная окружения `PATH` предваряется `C:\Windows\System32`, чтобы исключить сбои GNU tar из Git for Windows.
- **Минимальный дифференциал (Minimal-Diff):** никаких изменений в архитектуре ядра, добавлении новых пакетов или сторонних зависимостей не производится; задача строго следует регламенту синхронизации.

## Testing Decisions

- **Критерии надёжного теста:** проверка не внутренней реализации, а проверяемых контрактов форка (чистота каталогов воркфлоу, целостность манифестов, сборка всех целевых пакетов и 100% паритет словарей).
- **Тестируемые контуры:**
  - `pnpm run strata:audit-overrides` — проверка запрета активного Dependabot, отсутствия чужих воркфлоу и целостности переопределений.
  - `pnpm exec vitest run scripts/strata/russian-localization-parity.spec.ts` — проверка паритета пространств имён русской локализации.
  - `pnpm run constraints` — проверка монорепозиторных зависимостей pnpm.
  - `pnpm run build` — компиляция всех пакетов монорепозитория (`build:artifacts` + `build:check`).
  - `pnpm --filter @deepseek-ai/dsh-desktop run check:package` — проверка готовности десктопного бандла.
  - `pnpm --filter @deepseek-ai/dsh-desktop run test:updates:local` — smoke-проверка инфраструктуры локальных обновлений.

## Out of Scope

- Выпуск и тегирование релиза `strata-v1.0.1` через `/strata-release` (выполняется отдельным шагом).
- Модификация системных промптов или логики агента, не затронутой апстримом `rc.5`.
- Добавление новых переводов за пределами контрактов, изменённых в `rc.5`.
