# Спецификация 0005: Обновление StrataHarness Desktop через GitHub Releases и компактные подписи индикатора обновлений (`github-releases-auto-update`)

- **Статус триажа:** `ready-for-agent`
- **Категория:** `Development` / `Feature`
- **Фича:** `github-releases-auto-update`
- **Связанные документы:** [`.agents/CONTEXT.md`](../../.agents/CONTEXT.md), [`docs/strata/fork-maintenance.md`](../strata/fork-maintenance.md), [`.agents/notes/implemented/process/2026-10-29-strata-release-distribution-and-upstream-radar.md`](../../.agents/notes/implemented/process/2026-10-29-strata-release-distribution-and-upstream-radar.md)

## Problem Statement

В текущих десктопных релизах `StrataHarness` (`strata-v1.0.0`, `strata-v1.0.1`), публикуемых через GitHub Releases в режиме `unsigned` (до подключения платных сертификатов подписи Windows Authenticode и Apple Developer ID и внешнего CDN `DOWNLOAD_PROD_ORIGIN`), проверка и установка обновлений из приложения не работают, а интерфейс боковой панели на русском языке страдает от визуального перекрытия:

1. **Ошибка отсутствия источника обновлений (`no packaged update source`):** при сборке без `DOWNLOAD_PROD_ORIGIN` (и во всех `unsigned`-сборках) упаковщик не создаёт `resources/app-update.yml`, чтобы `electron-updater` не пытался выполнять тихую фоновую замену неподписанных бандлов (которая на macOS блокируется `Squirrel.Mac`, а на Windows требует подписи издателя). В результате при нажатии пользователем кнопки «Проверить обновления…» координатор обновлений выбрасывает ошибку `desktop update: this application has no packaged update source`, хотя в публичных GitHub Releases репозитория продукта уже лежат готовые установочные пакеты под все три платформы и файл контрольных сумм `SHA256SUMS.txt`.
2. **Обрезка кнопки «Настройки» в нижней строке боковой панели:** в русской локализации (`@strata/locale-ru`) текстовые метки пилюли индикатора обновлений (`Повторить обновление`, `Проверка обновлений…`, `Проверка файлов обновления…`, `Подготовка к перезапуску…`, `Установить и перезапустить`) имеют длину 20–27 символов. Поскольку пилюля располагается в одной flex-строке справа от кнопки `⚙️ Настройки` в боковой панели шириной 240 пикселей и имеет `flex: none`, длинная надпись вытесняет кнопку настроек, обрезая слово «Настройки» до «Настро».

## Solution

Реализовать двухконтурный механизм доставки обновлений десктопного приложения с встроенным провайдером GitHub Releases и компактными русскими подписями индикатора обновлений:

1. **Декларация репозитория релизов продукта (`releaseRepository`):** зафиксировать канонический GitHub-репозиторий дистрибуции в корневом манифесте продукта (`strata-product.json`), проверять его изолированность от апстрима (`deepseek-ai/deepseek-harness`) и запечатывать в метаданные упакованного приложения (`dshReleaseRepository`).
2. **Встроенный провайдер обновлений через GitHub Releases (`GitHubReleaseUpdater`):** когда в упакованном приложении присутствует `resources/app-update.yml` (режим `signed` с внешним статическим фидом `DOWNLOAD_PROD_ORIGIN`), использовать штатный `electron-updater`; когда `app-update.yml` отсутствует, но в манифесте приложения задан `dshReleaseRepository`, автоматически подключать совместимый с координатором обновлений адаптер GitHub Releases.
3. **Проверка, загрузка с верификацией `SHA256SUMS.txt` и установка:**
   - При автоматической (по расписанию) или ручной проверке адаптер запрашивает опубликованные релизы `strata-v<version>` из GitHub Releases API репозитория продукта (учитывая пререлизы только тогда, когда установленная версия сама является пререлизом или активен канал `nightly`, и трактуя отсутствие опубликованных релизов `404` как актуальное состояние `idle`).
   - При наличии новой версии пользователю показывается стандартное уведомление. При подтверждении загрузки адаптер выбирает платформенный установщик для текущей ОС и архитектуры (`win-x64` → `.exe`, `mac-arm64` / `mac-x64` → `.dmg`) с приоритетом подписанного файла (`strataharness-<version>-<target>.<ext>`) над неподписанным (`strataharness-<version>-<target>-unsigned.<ext>`), скачивает его во временный каталог с трансляцией прогресса `0%…100%`, загружает `SHA256SUMS.txt` из того же релиза и проверяет `SHA-256` дайджест.
   - При совпадении контрольной суммы обновление переходит в фазу готовности (`ready`). По нажатию «Установить и перезапустить» после штатной остановки активных задач и закрытия хоста (`beforeRestart`) на Windows запускается проверенный `.exe`-инсталлятор (`detached: true`) с закрытием приложения, а на macOS монтируется/открывается проверенный образ `.dmg` (`shell.openPath`) с закрытием приложения.
4. **Компактные русские подписи пилюли обновлений в боковой панели:** сократить строки `desktop.update.*` для пилюли в `@strata/locale-ru` до 9–13 символов (`Обновление`, `Проверка…`, `Перезапуск…`, `Перезапустить`), сохранив полные разъяснения во всплывающем тултипе и диалоговых окнах, чтобы кнопка `⚙️ Настройки` всегда отображалась целиком.

## User Stories

1. Как пользователь `StrataHarness Desktop`, нажимающий «Проверить обновления…» на актуальной установленной сборке, я хочу видеть сообщение «Установлена актуальная версия» с номером моей версии вместо технической ошибки `no packaged update source`, чтобы быть уверенным, что приложение работает исправно.
2. Как пользователь `StrataHarness Desktop` из России или любой другой страны без VPN, я хочу, чтобы приложение проверяло и скачивало новые релизы напрямую из GitHub Releases без необходимости настраивать сторонние прокси или внешние CDN-серверы.
3. Как пользователь `StrataHarness Desktop`, я хочу, чтобы приложение автоматически в фоне проверяло выход новых версий `strata-v*` на GitHub и зажигало кнопку «Обновление» в боковой панели, чтобы я узнавал о новых версиях без ручного посещения GitHub.
4. Как пользователь `StrataHarness Desktop`, когда на GitHub выходит новая версия, я хочу нажать «Загрузить обновление» и видеть прогресс скачивания `0%…100%` прямо в интерфейсе приложения, чтобы не искать нужный файл под свою архитектуру вручную среди ассетов релиза.
5. Как пользователь `StrataHarness Desktop`, я хочу, чтобы перед предложением установить скачанный из GitHub файл приложение автоматически сверяло его контрольную сумму `SHA-256` с файлом `SHA256SUMS.txt` релиза и удаляло файл при любом расхождении, чтобы исключить запуск повреждённого или неполного установщика.
6. Как пользователь на Windows (`win-x64`), нажавший «Установить и перезапустить» после загрузки обновления с GitHub, я хочу, чтобы приложение безопасно остановило активные задачи агента, запустило скачанный установщик `.exe` и закрылось для обновления.
7. Как пользователь на macOS (`mac-arm64` или `mac-x64`) на `unsigned`-сборке, нажавший «Установить и перезапустить», я хочу, чтобы приложение безопасно остановило активные задачи, автоматически открыло проверенный образ `.dmg` в Finder и закрылось, чтобы я мог сразу перетащить обновлённый `StrataHarness.app` в `/Applications`.
8. Как пользователь на стабильной версии `1.0.1`, я хочу, чтобы приложение предлагало мне только финальные стабильные релизы (`prerelease: false`) и игнорировало черновики (`draft: true`) и тестовые пререлизы.
9. Как пользователь русскоязычного интерфейса, я хочу, чтобы в нижней строке боковой панели рядом с пилюлей статуса обновления надпись «⚙️ Настройки» всегда помещалась полностью и не обрезалась до «Настро» ни при ошибке проверки, ни во время проверки или подготовки к перезапуску.
10. Как пользователь русскоязычного интерфейса, наводящий курсор на компактную пилюлю «Обновление» с точкой индикатора сбоя, я хочу видеть во всплывающем тултипе полное объяснение причины («Не удалось проверить обновления. Повторите попытку позже.»), а по клику на пилюлю — запускать повторную проверку или открывать диалог обновления.
11. Как системный архитектор `StrataHarness`, я хочу, чтобы при подключении в будущем платных сертификатов подписи и секрета `DOWNLOAD_PROD_ORIGIN` приложение автоматически переключалось на `electron-updater` (`app-update.yml`) без изменения кода, сохраняя GitHub Releases как штатный контур для сборок без внешнего CDN.

## Implementation Decisions

- **Поле `releaseRepository` в манифесте продукта:** корневой манифест продукта дополняется обязательным строковым полем `releaseRepository`, указывающим на GitHub-репозиторий дистрибуции продукта (`https://github.com/cannoneer85-svg/strataharness-app.git`). Валидатор конфигурации десктопа и аудит `Soft-Fork` проверяют, что `releaseRepository` является валидным HTTPS URL репозитория GitHub (`github.com/<owner>/<repo>[.git]`) и не указывает на апстрим-репозиторий `deepseek-ai/deepseek-harness`.
- **Запечатывание `dshReleaseRepository` при упаковке:** конфигурация `electron-builder` записывает нормализованный идентификатор репозитория `<owner>/<repo>` (или HTTPS URL) в `extraMetadata.dshReleaseRepository` внутри `package.json` приложения, чтобы упакованное приложение знало свой источник релизов на GitHub независимо от наличия `resources/app-update.yml`.
- **Единый шов координатора обновлений (`Minimal-Diff`):** вместо дублирования конечного автомата `DesktopUpdateCoordinator`, расписания `DesktopUpdateSchedule` или IPC-сообщений между главным процессом и рендерером, создаётся адаптер `GitHubReleaseUpdater`, реализующий контракт `AppUpdater`, который ожидает `DesktopUpdateCoordinator` (`checkForUpdates`, `downloadUpdate`, `quitAndInstall` и события `'download-progress'`, `'update-downloaded'`, `'error'`).
- **Приоритет источников обновления:**
  1. Если приложение упаковано (`app.isPackaged === true`) и существует `resources/app-update.yml` — используется штатный `electron-updater` (`autoUpdater`).
  2. Если приложение упаковано (`app.isPackaged === true`), `resources/app-update.yml` отсутствует, но в `package.json` задан `dshReleaseRepository` — используется `GitHubReleaseUpdater`.
  3. Если приложение запущено в режиме разработки (`!app.isPackaged`) и источник не переопределён в тестах — `enabled()` возвращает `false`.
- **Правила выбора релиза в GitHub Releases API:**
  - Запрашивается список релизов репозитория `https://api.github.com/repos/<owner>/<repo>/releases?per_page=20` с заголовками `Accept: application/vnd.github+json` и `User-Agent: StrataHarness/<currentVersion>` и контролем таймаута неактивности соединения.
  - Отфильтровываются черновики (`draft === true`) и релизы, чей `tag_name` не начинается с канонического префикса `strata-v` или не содержит валидный SemVer без build-метаданных.
  - Если текущая версия приложения стабильная (`semver.prerelease(currentVersion) === null`), релизы с `prerelease === true` (или SemVer-пререлизом в теге) пропускаются; если текущая версия сама является пререлизом, пререлизы допускаются.
  - Среди подходящих релизов выбирается максимальный по `semver.rcompare`. Если подходящих релизов нет (или API вернул `404`), `checkForUpdates()` возвращает `{ isUpdateAvailable: false, updateInfo: { version: currentVersion } }`, что переводит координатор в состояние `phase: 'idle'` («Установлена актуальная версия»).
- **Выбор платформенного установщика и проверка `SHA256SUMS.txt`:**
  - Для целевой платформы (`win32` + `x64` → `win-x64`, расширение `.exe`; `darwin` + `arm64` → `mac-arm64`, расширение `.dmg`; `darwin` + `x64` → `mac-x64`, расширение `.dmg`) в массиве `assets` выбранного релиза сначала ищется подписанный файл `strataharness-<version>-<target>.<ext>`, а при его отсутствии — неподписанный `strataharness-<version>-<target>-unsigned.<ext>`.
  - Также в `assets` обязательно ищется файл `SHA256SUMS.txt`. Если целевой установщик или `SHA256SUMS.txt` отсутствуют в релизе, загрузка завершается ошибкой.
  - Во время скачивания установщика во временный каталог (`mkdtemp` в системном `tmpdir`) по мере чтения потока вычисляется `SHA-256` хеш и публикуются события `'download-progress'` (`percent` от `0` до `99`).
  - После завершения записи файла публикуется `'download-progress'` с `percent: 100` (переводящий индикатор в фазу `verifying` — «Проверка…»), скачивается и парсится `SHA256SUMS.txt`, и вычисленный `SHA-256` сверяется в регистронезависимом режиме со строкой для имени скачанного файла. При несовпадении хеша или ошибке чтения `SHA256SUMS.txt` временный каталог с файлом немедленно удаляется, и выбрасывается ошибка загрузки. При успехе эмитится `'update-downloaded'` (`{ version }`).
- **Запуск установщика (`quitAndInstall`):**
  - На Windows (`win32`) запускается проверенный `.exe`-файл через `spawn(installerPath, [], { detached: true, stdio: 'ignore', windowsHide: false })` с ожиданием события `'spawn'`; после успешного старта дочернего процесса вызывается `unref()` и `app.quit()`.
  - На macOS (`darwin`) вызывается `shell.openPath(installerPath)` для открытия проверенного `.dmg`-образа в Finder; если `openPath` вернул пустую строку (успех), вызывается `app.quit()`, иначе эмитится событие `'error'` с текстом ошибки.
- **Компактные русские строки пилюли индикатора (`@strata/locale-ru`):** в словаре `ruSettings` обновляются ключи:
  - `'desktop.update.available': 'Обновление'`
  - `'desktop.update.retry': 'Обновление'`
  - `'desktop.update.checking': 'Проверка…'`
  - `'desktop.update.verifying': 'Проверка…'`
  - `'desktop.update.installing': 'Перезапуск…'`
  - `'desktop.update.ready': 'Перезапустить'`
- **Оценка Minimal-Diff и зависимостей:** новые внешние npm-пакеты не требуются — используются встроенные в Node.js и Electron примитивы (`crypto.createHash`, `fs`, `child_process.spawn`, `shell.openPath`) и существующая инфраструктура таймаутов и координации обновлений.

## Testing Decisions

- **Что делает тест хорошим:** тесты проверяют наблюдаемое внешнее поведение через публичные швы (состояния `DesktopUpdateCoordinator`, фильтрацию релизов, проверку `SHA-256`, удаление файла при расхождении хеша, инварианты `strata:audit-overrides` и 100% паритет русской локализации), не привязываясь к приватным полям.
- **Швы тестирования (Seams):**
  1. **Шов координатора и провайдера GitHub Releases (`DesktopUpdateCoordinator` + `GitHubReleaseUpdater`):** модульные и интеграционные тесты в `apps/desktop/tests/` с подменой сетевого транспорта (HTTP-ответов GitHub API и потоков скачивания ассетов) и функции запуска установщика (`spawn` / `openPath`), проверяющие весь жизненный цикл `idle` → `available` → `downloading` → `verifying` → `ready` → `installing` и все сценарии отказа (`404`, отсутствие ассета, отсутствие `SHA256SUMS.txt`, несовпадение `SHA-256`, ошибка запуска установщика).
  2. **Шов конфигурации продукта и аудита `Soft-Fork` (`strata-desktop-config.mjs` + `fork-ops.ts`):** тесты в `scripts/strata/fork-ops.spec.ts`, проверяющие валидацию `releaseRepository` в `strata-product.json` и блокировку указания апстрим-репозитория в качестве `releaseRepository`.
  3. **Шов русской локализации (`@strata/locale-ru`):** `scripts/strata/russian-localization-parity.spec.ts`, проверяющий полноту ключей и компактную длину подписей индикатора обновлений в `ruSettings`.
- **Существующие аналоги (Prior art):** `apps/desktop/tests/update-coordinator.spec.ts`, `scripts/strata/fork-ops.spec.ts`, `scripts/strata/russian-localization-parity.spec.ts`.

## Acceptance Criteria

1. `[auto]` В `strata-product.json` объявлено поле `"releaseRepository": "https://github.com/cannoneer85-svg/strataharness-app.git"`, которое сохраняется при вызове `bumpStrataVersion` (`pnpm run strata:version`) и валидируется гейтом `pnpm run strata:audit-overrides`.
2. `[auto]` Валидатор конфигурации отвергает пустой `releaseRepository`, не-HTTPS/не-GitHub URL и URL апстрим-репозитория `deepseek-ai/deepseek-harness`.
3. `[auto]` Конфигурация `electron-builder` пробрасывает `dshReleaseRepository` в `extraMetadata` упакованного приложения.
4. `[auto]` Когда `resources/app-update.yml` отсутствует, а `dshReleaseRepository` задан, проверка обновлений обращается к GitHub Releases API целевого репозитория и НЕ выбрасывает ошибку `desktop update: this application has no packaged update source`.
5. `[auto]` Если на GitHub нет опубликованных релизов (`404` или только `draft`) либо последняя версия `strata-v*` меньше или равна `app.getVersion()`, проверка возвращает `phase: 'idle'` («Установлена актуальная версия»).
6. `[auto]` На стабильной установленной версии (`1.0.1`) пререлизы (`prerelease: true` или тег с `-rc.*`) игнорируются; на пререлизной установленной версии пререлизы учитываются.
7. `[auto]` Если на GitHub опубликован более новый релиз `strata-v<version>`, проверка переводит координатор в `phase: 'available'` с версией `<version>`, причём приоритет отдаётся подписанному ассету (`strataharness-<version>-<target>.<ext>`) перед `-unsigned` (`strataharness-<version>-<target>-unsigned.<ext>`).
8. `[auto]` При вызове `download(version)` установщик скачивается с эмиссией прогресса `0%…100%`, после чего скачивается `SHA256SUMS.txt` и проверяется `SHA-256` хеш скачанного файла. При совпадении хеша координатор переходит в `phase: 'ready'`.
9. `[auto]` Если в релизе отсутствует подходящий под платформу установщик, отсутствует `SHA256SUMS.txt` или `SHA-256` хеш скачанного файла не совпадает с записью в `SHA256SUMS.txt`, временный файл немедленно удаляется, а `download(version)` возвращает `phase: 'error'` с `failedOperation: 'download'`.
10. `[auto]` При вызове `install(version)` после успешного `beforeRestart()` на Windows запускается скачанный `.exe` (`detached: true`) и вызывается выход из приложения, а на macOS открывается проверенный `.dmg` (`shell.openPath`) и вызывается выход из приложения.
11. `[auto]` В `packages/strata/locale-ru/src/client/locales/settings.ts` строки пилюли индикатора обновлений (`desktop.update.available`, `desktop.update.retry`, `desktop.update.checking`, `desktop.update.verifying`, `desktop.update.installing`, `desktop.update.ready`) используют утверждённый компактный набор (`Обновление`, `Проверка…`, `Перезапуск…`, `Перезапустить`) длиной не более 13 символов.
12. `[manual]` В нижней строке боковой панели при ширине сайдбара по умолчанию (240 px) надпись «⚙️ Настройки» и пилюля «Обновление» отображаются рядом на одной строке без обрезки слова «Настройки».

## Out of Scope

- Покупка и выпуск платных сертификатов Apple Developer ID и Windows Authenticode (выполняется организационно через секреты репозитория согласно `docs/strata/fork-maintenance.md`).
- Поднятие отдельного облачного S3 / Cloudflare R2 сервера для раздачи обновлений.
- Бесшовная фоновая замена `.app` через `Squirrel.Mac` на macOS для неподписанных (`-unsigned`) сборок (невозможна из-за системных ограничений безопасности macOS Gatekeeper / Code Signing).
