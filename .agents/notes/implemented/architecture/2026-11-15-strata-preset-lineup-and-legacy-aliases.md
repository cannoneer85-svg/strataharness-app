# Agent Note: Strata role preset lineup, non-ceremonial standard mode, and legacy preset ID aliases

Status: implemented

English | [中文](2026-11-15-strata-preset-lineup-and-legacy-aliases.zh.md)

## Problem

In `strata-v1.0.0` through `strata-v1.0.2`, the [product bundle patch](../../../../packages/strata/product-bundle/cordis.patch.yml) exposed four built-in role presets (`strata`, `strata-developer`, `strata-analyst`, and `strata-designer`) while disabling the upstream `standard`, `ptc`, `minimal`, and `cordis` presets (see [dual-track product versioning](2026-10-29-strata-dual-track-product-versioning.md)). Both `strata` and `strata-developer` composed the same six-stage stop-gate methodology workflow and identical toolset, creating visible duplication in settings and preset selectors while leaving users without a direct non-ceremonial coding mode equivalent to upstream `standard`.

Removing `strata` outright would break previously saved `strata-v1.0.x` sessions whose session log header records `agentPreset: "strata"` and user configurations with `selectedDefault: "strata"` by raising `agent-preset/not-found` inside [AgentPresetRegistry](../../../../packages/preset/agent-preset-registry/src/index.ts). Re-enabling upstream `standard` alone is also insufficient: in workspaces that carry a StrataHarness template `AGENTS.md`, upstream `standard` reads Step 0 classification and multi-stage stop-gate rules without an instruction telling the model to follow coding standards while skipping methodology ceremonies unless explicitly asked. Finally, enabling `cordis` on the backend without adding it alongside `ptc` in `requiresCodingTools` inside the [client preset settings store](../../../../packages/client/ui-agent-preset/src/client/settings-store.ts) leaves `cordis` and its creator-draft entry visible even when Developer tools are switched off.

## Decision

StrataHarness structures its built-in preset lineup as a four-mode default roster plus two opt-in coding-tools modes, backed by lookup-time aliasing and declarative Soft-Fork overlays inside `@strata/product-bundle`:

1. **Non-redundant core roster (`strata-developer` default):** The duplicate `strata` preset definition is removed from `@strata/product-bundle`, exposing four built-in modes by default through the [product bundle patch](../../../../packages/strata/product-bundle/cordis.patch.yml) and per-preset files in `packages/strata/product-bundle/presets/`: `strata-developer` (`order: 1`, registry `default`), `standard` (`order: 2`), `strata-analyst` (`order: 3`), and `strata-designer` (`order: 4`). Both `ptc` (`order: 5`) and `cordis` (`order: 6`) are enabled on the backend while `minimal` stays disabled, and `requiresCodingTools` (`ptc`, `minimal`, `cordis`) in the [client preset settings store](../../../../packages/client/ui-agent-preset/src/client/settings-store.ts) keeps `ptc`, `cordis`, and the Settings creator-draft entry hidden until Developer tools (`developerTools`) are enabled.
2. **Transparent legacy preset ID aliasing (`aliases`):** `AgentPresetRegistry.Config` exposes a validated `aliases: Record<string, string>` field (defaulting to `{}` in [preset configuration](../../../../packages/preset/agent-preset-registry/src/preset.ts)), configured with `{ strata: 'strata-developer' }` in the [product bundle patch](../../../../packages/strata/product-bundle/cordis.patch.yml). [AgentPresetRegistry](../../../../packages/preset/agent-preset-registry/src/index.ts) normalizes requested preset IDs through `aliases` across `defaultId`, `resolve()`, `retain()`, and `readDocument()` while emitting only canonical preset definitions from `list()`, and the client mirrors this with `LEGACY_PRESET_ALIASES` and `findPresetOption` so `strata-v1.0.x` sessions and `selectedDefault: "strata"` resolve to `strata-developer` and highlight it as active default without reintroducing `strata` to the UI roster.
3. **Declarative Soft-Fork preset overlays and Office tools (`dsh-v0.2.2-rc.3`):** Instead of editing upstream files under `packages/bundle/web-app/presets/`, `@strata/product-bundle` overlays `preset-standard`, `preset-ptc`, and `preset-cordis` inside `packages/strata/product-bundle/presets/` alongside `strata-developer`, `strata-analyst`, and `strata-designer`. All six active presets standardize `tool-result-pruner` (`thresholdChars: 32768`, `headChars: 16384`, `tailChars: 4096`); `standard` configures a compact static `persona.prefix` honoring workspace `AGENTS.md` technical conventions, test commands, and git guardrails while skipping Step 0 classification and stop-gate prompts unless explicitly requested; `strata-developer` adds a soft optional workspace initialization step (`AGENTS.md`, `.agents/CONTEXT.md`, ADR directories) with non-`pwsh` file fallbacks; and Desktop Office document generation runs through Host `@deepseek-ai/dsh-skill-office` (configured in the [web-app Host patch](../../../../packages/bundle/web-app/cordis.patch.yml)) plus per-preset `@deepseek-ai/dsh-tool-office` (`id: tool-office`) in `strata-developer`, `standard`, `strata-analyst`, and `ptc`, alongside `dsh-v0.2.2-rc.3`-aligned `delegation` groups (`workflowEngine: true` and `@deepseek-ai/dsh-tool-subagent-control`).
4. **Russian localization and card header layout:** The [Soft-Fork Russian language pack](2026-10-31-strata-russian-localization-pack.md) and `@strata/locale-ru` align localized preset names and descriptions with the `41` methodology skills in `resources/strataharness` `v1.4.6`, shorten the Russian `inUse` badge to `'По умолчанию'`, and wrap preset card headers in `ui-agent-preset` so titles remain legible beside the badge and preset ID.

## Alternatives considered

**Keep both `strata` and `strata-developer` visible in the preset selector.** Keeping both presets perpetuates user confusion between two identical engineering workflows while still omitting a non-ceremonial direct coding mode.

**Remove `strata-developer` and keep `strata` as the single engineering mode.** Preserving `strata` breaks naming symmetry alongside `strata-analyst` and `strata-designer` and still requires an alias table for existing `strata-developer` sessions.

**Mutate historical session files on disk to rewrite `agentPreset`.** Rewriting append-only session logs violates event-sourced session durability and fails on read-only, exported, or externally shared sessions, whereas lookup-time aliasing handles every historical session without disk mutation.

**Edit upstream `standard`, `ptc`, and `cordis` patch files directly.** Modifying files inside `packages/bundle/web-app/presets/` widens the `strata(override)` conflict footprint on `dsh-v*` upstream merges, whereas composing overrides inside `@strata/product-bundle` isolates product policy cleanly.

## Consequences

- With Developer tools disabled, the client selector and settings roster display four built-in presets in order (`strata-developer` marked as default, `standard`, `strata-analyst`, and `strata-designer`) without `strata` or the creator-draft button; enabling Developer tools reveals `ptc`, `cordis`, and the creator-draft action while keeping `minimal` disabled.
- Opening a saved `strata-v1.0.x` session with `agentPreset: "strata"` or evaluating settings with `selectedDefault: "strata"` succeeds via `AgentPresetRegistry` and `findPresetOption`, resolves to `strata-developer`, and never lists `strata` as a separate option.
- Upstream `standard`, `ptc`, and `cordis` inherit Soft-Fork `persona.prefix`, `tool-result-pruner`, and `tool-office` policies declaratively inside `@strata/product-bundle` while upstream `packages/bundle/web-app/presets/` remain untouched, and Office runtime initialization in Desktop aligns with the `dsh-v0.2.2-rc.3` Host/preset contract.

Mapping `strata` to `strata-developer` routes legacy `strata` sessions through `strata-developer`'s system prompt and tools; compatibility impact is negligible because both presets mounted equivalent tools and methodology lifecycle rules. Suppressing `AGENTS.md` stop-gates in `standard` relies on instruction precedence in its `persona.prefix` overlay, which is covered by `@strata/product-bundle` preset composition tests.
