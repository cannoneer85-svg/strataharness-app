# Agent Note: Strata 角色预设阵容、无仪式标准模式与旧版预设 ID 别名

Status: implemented

[English](2026-11-15-strata-preset-lineup-and-legacy-aliases.md) | 中文

## 问题

在 `strata-v1.0.0` 至 `strata-v1.0.2` 中，[产品组合包补丁](../../../../packages/strata/product-bundle/cordis.patch.yml) 暴露了四个内置角色预设（`strata`、`strata-developer`、`strata-analyst` 与 `strata-designer`），同时禁用了上游的 `standard`、`ptc`、`minimal` 与 `cordis` 预设（参见[双轨产品版本管理](2026-10-29-strata-dual-track-product-versioning.zh.md)）。`strata` 与 `strata-developer` 组合了完全相同的六阶段停止门方法论工作流和完全一致的工具集，在设置和预设选择器中造成明显重复，同时也使用户缺少等同于上游 `standard` 的直接无仪式编码模式。

若直接移除 `strata`，则在 [AgentPresetRegistry](../../../../packages/preset/agent-preset-registry/src/index.ts) 中打开会话日志头部记录为 `agentPreset: "strata"` 的旧版 `strata-v1.0.x` 会话，或加载仍保留 `default: strata` / `selectedDefault: strata` 的升级后用户配置 `profiles/desktop/cordis.patch.yml`（尤其是当 `applyPatches` 整块替换 `agent-preset-registry` 的 `config` 并抹除 `@strata/product-bundle` 声明的 `aliases` 时），会因抛出 `agent-preset/not-found` 而失败并清空默认徽章。仅重新启用上游 `standard` 也不充分：在包含 StrataHarness 模板 `AGENTS.md` 的工作区中，上游 `standard` 会读取 Step 0 分类和多阶段停止门规则，却缺乏指示模型遵循代码规范但跳过方法论仪式的指令（除非用户明确要求），而继续启用 `ptc` 与 `cordis` 也会使围绕 `standard` 为首的四模式选择变得杂乱。此外，角色预设（`strata-developer`、`strata-analyst` 与 `strata-designer`）需要可在新项目中自动准备项目记忆起始文件（且不复制 `.agents/skills/` 或要求用户手动执行 `/init-project`），所有启用预设需与 `AGENTS.md`、`CLAUDE.md` 一并自动加载 `CODING_STANDARDS.md`，且 macOS Intel 冷启动时 Desktop Office 转换会超出 `office-kit` 上游默认的 `60_000` ms 超时。

## 决策

StrataHarness 在 `@strata/product-bundle` 内将内置预设阵容组织为以 `standard` 为首的四模式阵容，并辅以 Schema 默认别名保护、Desktop 配置迁移、自动工作区骨架初始化与声明式 Soft-Fork 覆盖层：

1. **精简核心四模式阵容（`standard` 居首并默认；`minimal`、`ptc`、`cordis` 禁用）：** 从 `@strata/product-bundle` 移除重复的 `strata` 预设定义以及 `presets/ptc.patch.yml`、`presets/cordis.patch.yml` 覆盖文件，通过[产品组合包补丁](../../../../packages/strata/product-bundle/cordis.patch.yml) 与 `packages/strata/product-bundle/presets/` 精确暴露四个内置模式：`standard`（`order: 1`，注册表 `default`）、`strata-developer`（`order: 2`）、`strata-analyst`（`order: 3`）和 `strata-designer`（`order: 4`）。`preset-minimal`、`preset-ptc` 与 `preset-cordis` 在 `@strata/product-bundle/cordis.patch.yml` 中保持 `disabled: true`，同时[客户端预设设置存储](../../../../packages/client/ui-agent-preset/src/client/settings-store.ts) 保留 `requiresCodingTools`（`ptc`、`minimal`、`cordis`）以兼容外部启用它们的配置。`standard` 在 `skill-filesystem` 中不挂载 `bundledSkillDir`（使无仪式模式保持不含 `41` 个 `Strata` 方法论技能），而 `strata-developer`、`strata-analyst` 与 `strata-designer` 均挂载 `bundledSkillDir: ctx.strataPaths.bundledSkillsDir`（`strata-designer` 还额外挂载 `customSkillDirs: [ctx.strataPaths.designerSkillsDir]`）。
2. **旧版别名保护、安全 `defaultId` 回退与 Desktop 配置迁移（`AgentPresetRegistry` + `DesktopProjectManager`）：** `AgentPresetRegistry.Config` 提供经校验的 `aliases: Record<string, string>` 字段（见[预设配置](../../../../packages/preset/agent-preset-registry/src/preset.ts)），其在 [AgentPresetRegistry](../../../../packages/preset/agent-preset-registry/src/index.ts) 的 Schema 默认值为 `{ strata: 'strata-developer' }`，确保用户补丁覆盖 `agent-preset-registry.config` 但未声明 `aliases` 时仍保留 `strata` 别名映射。`AgentPresetRegistry` 在 `defaultId`、`resolve()`、`retain()` 和 `readDocument()` 中通过 `aliases` 规范化请求 ID 同时仅在 `list()` 中输出规范预设定义，`defaultId` 会核验解析结果是否存在于 `this.definitions`（当 `selectedDefault` 指向禁用或未知预设时依次回退到规范化的 `config.default` 与首个已注册预设 ID）。客户端通过 `LEGACY_PRESET_ALIASES` 与 `findPresetOption` 镜像 `strata -> strata-developer`；Desktop 启动时，[DesktopProjectManager](../../../../apps/desktop/src/project-manager.ts) 内的 `migrateProfileSettings` 会清理 `profiles/desktop/cordis.patch.yml` 中 `agent-preset-registry` 里的旧版 `default: 'strata'` 与 `selectedDefault: 'strata'`（若条目为空则移除，或将文件折叠为 `[]`，同时保留其余用户配置与 `!!js` 表达式），将 `1.0.x` 用户平滑迁移至默认 `standard`。
3. **自动工作区骨架初始化（`@strata/product-bundle/workspace-scaffold`）与 `CODING_STANDARDS.md` 加载：** [工作区骨架插件](../../../../packages/strata/product-bundle/src/workspace-scaffold.ts)（`id: strata-workspace-scaffold`，导出为 `@strata/product-bundle/workspace-scaffold`）在 `strata-developer`、`strata-analyst` 与 `strata-designer` 中严格挂载在 `@deepseek-ai/dsh-agent-instructions` 之前（`standard` 不挂载）。在 `agent/pre-step` 移交 `await next()` 之前，该插件通过 `ctx.workingDirectory.ensure(agent, signal)` 获取会话工作目录，跳过受保护路径（空路径、文件系统根目录 `dirname(resolved) === resolved`、`os.homedir()` 与 `os.tmpdir()`，在 `win32` 和 `darwin` 上大小写不敏感比较），按目录缓存已处理路径，确保 `.agents` 与 `docs/{adr,agents,analysis,handoff,research,specs}` 存在，并使用独占创建标志（`flag: 'wx'`，忽略 `EEXIST`）从 `{{strata_root}}/.agents/skills/init-project/templates/` 写入缺失的起始文件：`CODING_STANDARDS.md`、`.agents/CONTEXT.md`、`docs/handoff/LATEST.md`、`docs/agents/domain.md`、`docs/agents/issue-tracker.md`（源自 `issue-tracker-local.md`）与 `docs/agents/triage-labels.md`，同时不复制 `.agents/skills/` 或 `AGENTS.md`。非中止类文件系统错误（`EACCES`、`EPERM`、`EROFS` 等）仅通过 `ctx.logger.warn` 记录警告而不中断当前步骤，`AbortSignal` 取消则正常抛出。全部四个启用预设（`standard`、`strata-developer`、`strata-analyst`、`strata-designer`）均将 `@deepseek-ai/dsh-agent-instructions` 配置为 `maxBytes: 65536` 与 `instructionFileCandidates: ['AGENTS.md', 'CLAUDE.md', 'CODING_STANDARDS.md']`，确保新建或仓库既有的 `CODING_STANDARDS.md` 在首步即进入模型上下文；`strata-developer` 的 `persona.prefix` 则移除 Step 0 手动调用 `/init-project` 的提示。
4. **声明式 Soft-Fork 预设覆盖、Office 工具（`dsh-v0.2.2-rc.3`）与 `office-kit` 超时：** `@strata/product-bundle` 不直接修改 `packages/bundle/web-app/presets/` 或 `packages/document/office-kit/` 下的上游文件，而是在 `packages/strata/product-bundle/presets/` 中覆盖 `preset-standard` 并与 `strata-developer`、`strata-analyst`、`strata-designer` 一并组合。四个启用预设统一配置 `tool-result-pruner`（`thresholdChars: 32768`、`headChars: 16384`、`tailChars: 4096`）；`standard` 配置紧凑且静态的 `persona.prefix`，指示代理遵守工作区 `AGENTS.md` 中的技术约定、测试命令与 git 安全护栏并跳过 Step 0 分类与停止门提示（除非用户明确要求）。Office 文档能力通过宿主层 `@deepseek-ai/dsh-skill-office`（挂载于 [web-app 宿主补丁](../../../../packages/bundle/web-app/cordis.patch.yml)）与预设级 `@deepseek-ai/dsh-tool-office`（`id: tool-office`，启用在 `standard`、`strata-developer` 与 `strata-analyst`）以及对齐 `dsh-v0.2.2-rc.3` 的 `delegation` 分组（`workflowEngine: true` 与 `interrupt: false` 的 `@deepseek-ai/dsh-tool-subagent-control`）协作实现。[产品组合包补丁](../../../../packages/strata/product-bundle/cordis.patch.yml) 将 `id: office-kit` 配置为 `timeoutMs: 120000`，而 [Desktop 冒烟运行时](../../../../apps/desktop/scripts/smoke-runtime.ts) 中的 `SMOKE_PROFILE_PATCH_YAML` 将 `id: office-kit` 配置为 `timeoutMs: 300000` 并配合相应的客户端 HTTP 截止时间，以适应受限的 `mac-x64` 打包环境。
5. **俄语本地化与卡片页头排版：** [Soft-Fork 俄语语言包](2026-10-31-strata-russian-localization-pack.zh.md) 与 `@strata/locale-ru` 将本地化预设名称、描述和 `ruPluginMetadataCatalog`（含 `@strata/product-bundle/workspace-scaffold`）与 `resources/strataharness` `v1.4.6` 的 `41` 个方法论技能同步，将俄语 `inUse` 徽章缩短为 `'По умолчанию'`，并在 `ui-agent-preset` 中调整预设卡片页头换行以防止标题被挤压截断。

## 曾考虑的替代方案

**在预设选择器中同时保留 `strata` 与 `strata-developer`，或同时暴露 `ptc` 与 `cordis`。** 同时保留两个 `strata` 模式会延续用户对两个完全相同工程工作流的困惑，而在主列表中继续启用 `ptc` 与 `cordis` 会分散以 `standard` 为首的四模式选择。

**移除 `strata-developer` 仅保留 `strata` 作为工程模式。** 保留 `strata` 会破坏其与 `strata-analyst`、`strata-designer` 之间的角色命名对称性，而且依然需要为现有 `strata-developer` 会话维护别名映射表。

**改写磁盘上历史会话文件中的 `agentPreset` 字段。** 修改追加写入式的会话日志会破坏事件溯源会话的不可变性，且在只读、导出或外部分享的会话文件上会失败；相比之下，查询期别名解析无需改动磁盘即可兼容全部历史会话。

**向每个用户工作区复制 `.agents/skills/` 或继续依赖手动执行 `/init-project`。** 向每个项目复制 `41` 个技能目录会重复内置资源并存在覆盖用户已有技能配置的风险，而依赖手动 `/init-project` 会使新项目缺少 `.agents/CONTEXT.md` 与 `CODING_STANDARDS.md`；`strata-workspace-scaffold` 在 `agent/pre-step` 仅幂等地创建缺失的项目记忆文件。

**直接修改上游 `packages/bundle/web-app/presets/` 补丁或 `@deepseek-ai/dsh-office-kit` 源码。** 修改上游预设补丁或在 `packages/document/office-kit/` 内硬编码修改默认 `60_000` ms 超时会在合并 `dsh-v*` 上游更新时扩大 `strata(override)` 冲突范围，而在 `@strata/product-bundle`（`120000` ms）与 `SMOKE_PROFILE_PATCH_YAML`（`300000` ms）中声明式组合覆盖 `office-kit` `timeoutMs` 可保持产品与打包策略清晰隔离。

## 后果

- 客户端选择器与设置列表按顺序精确显示四个内置预设（`standard` 标记为默认、`strata-developer`、`strata-analyst` 和 `strata-designer`），`minimal`、`ptc` 与 `cordis` 均禁用，不显示 `strata` 或创建者草稿入口，且 `standard` 保持不含内置 `Strata` 技能。
- 通过 `AgentPresetRegistry`（其 `aliases` Schema 默认为 `{ strata: 'strata-developer' }`）与 `findPresetOption` 打开包含 `agentPreset: "strata"` 的 `strata-v1.0.x` 已保存会话时无需改写磁盘即可解析到 `strata-developer`；当 `selectedDefault` 指向不可用预设时 `AgentPresetRegistry.defaultId` 会安全回退，且 `DesktopProjectManager` 在启动时清理 `profiles/desktop/cordis.patch.yml` 中的旧版 `default: 'strata'` / `selectedDefault: 'strata'` 而保留用户其余设置。
- 在 `strata-developer`、`strata-analyst` 与 `strata-designer` 的首个 `agent/pre-step` 阶段，工作区自动补齐缺失的 `.agents/CONTEXT.md`、`CODING_STANDARDS.md`、`docs/handoff/LATEST.md`、`docs/agents/*.md` 与 `docs/*` 目录，随后 `@deepseek-ai/dsh-agent-instructions` 在全部四个启用预设中一并加载 `['AGENTS.md', 'CLAUDE.md', 'CODING_STANDARDS.md']`，并安全跳过受保护系统根目录及软处理权限错误而不中断回合。
- 上游 `packages/bundle/web-app/presets/` 与 `@deepseek-ai/dsh-office-kit` 保持未改动，同时 Desktop/Web 配置以 `timeoutMs: 120000` 运行 `office-kit`，`SMOKE_PROFILE_PATCH_YAML` 则应用 `timeoutMs: 300000`。

将 `strata` 映射至 `strata-developer` 会让旧版 `strata` 会话沿用 `strata-developer` 的系统提示词与工具集；由于两者此前已挂载等效工具和方法论规则，此兼容性影响可忽略不计。在 `standard` 中抑制 `AGENTS.md` 停止门、保留 `aliases` 与 `defaultId` 回退、迁移 `profiles/desktop/cordis.patch.yml`、在 `agent/pre-step` 初始化工作区骨架、加载 `CODING_STANDARDS.md` 以及配置 `office-kit` 超时（产品配置 `120000` ms、Desktop 打包冒烟 `300000` ms）均由 `@strata/product-bundle`、`@deepseek-ai/dsh-agent-preset-registry`、`@deepseek-ai/dsh-agent-instructions`、`apps/desktop/tests/project-manager.spec.ts` 与 `apps/desktop/tests/smoke-runtime.spec.ts` 覆盖验证。
