# Agent Note: Soft-Fork Russian language pack isolation and default-locale contract

Status: implemented

English | [中文](2026-10-31-strata-russian-localization-pack.zh.md)

## Problem

StrataHarness ships as a managed Soft-Fork over upstream `dsh-v*` release tags of DeepSeek Harness (see [dual-track product versioning](2026-10-29-strata-dual-track-product-versioning.md)). Upstream ships only two client locales (`zh` and `en`) across 77 `LocaleNamespaceMap` namespaces (plus `directory-browser`) in `packages/client/*`, `packages/extensions/*`, `packages/session-query/*`, and `packages/experimental/*`, alongside more than three hundred `locale/en.json` and `locale/zh.json` plugin metadata directories and the 191-key Electron shell dictionary in `apps/desktop/src/locale.ts`.

StrataHarness requires complete Russian (`ru`) localization across the Web/Desktop client UI, Electron native menus and dialogs, built-in Strata role presets, and built-in plugin metadata, with `Русский` (`ru`) active by default whenever `locale.preference` is unset and ordered first in `Settings -> General -> Language` (`Русский` -> `English` -> `中文`). Expanding `BuiltInLocaleId` to `'ru' | 'en' | 'zh'` directly in `packages/client/locale` would force every `ctx.locale.register(ns, { zh, en })` call across upstream client packages and over two hundred upstream `locale/` directories to change, creating repository-wide merge conflicts on every `git merge dsh-v*`. Rewriting `FALLBACK_LOCALE` from `'en'` to `'ru'` unconditionally inside `LocaleRuntime` would break standalone upstream client unit tests (which construct `LocaleRuntime` without `@strata/product-bundle` and expect English/Chinese browser fallback) and break the terminal English dictionary-fallback invariant required by third-party plugins that ship only `en` copy. Finally, Russian counters require three plural categories (`one`, `few`, `many`) where upstream namespaces pass `{ count }` into a single template key.

## Decision

StrataHarness isolates Russian client dictionaries and built-in plugin metadata translations inside `@strata/locale-ru` (`packages/strata/locale-ru`), composed in `@strata/product-bundle/cordis.patch.yml` with phase-one client activation (`dsh.client.immediately = true`), while confining upstream core edits to narrow, audited `strata(override)` changes:

1. **Configurable default locale and display order on `@deepseek-ai/dsh-client-locale`:** `packages/client/locale` exposes validated Cordis `Config` fields (`defaultLocale?: LocaleId` and `localeOrder?: readonly LocaleId[]`). When `defaultLocale` is configured (set to `'ru'` by `@strata/product-bundle/cordis.patch.yml`) and no explicit `locale.preference` is stored, `LocaleRuntime` selects `defaultLocale` once registered instead of delegating to `navigator.languages`, while keeping `FALLBACK_LOCALE = 'en'` as the terminal per-key dictionary fallback (`ru -> en`) and preserving upstream default behavior in standalone tests where `Config` is omitted. `localeOrder: ['ru', 'en', 'zh']` orders `LocaleSnapshot.locales` deterministically regardless of registration order.
2. **Typed namespace dictionaries and centralized `LocalizedText` catalog in `@strata/locale-ru`:** `@strata/locale-ru` registers `'ru'` (`label: 'Русский'`, `fallback: 'en'`) via `ctx.locale.addLanguage` in Boot Phase 1 (`immediately: true`, preventing startup locale flash while `dsh-client-locale` defers initial `<html lang>` and `__DSH_LOCALE__.onChange` synchronization until the requested locale settles) and registers all 78 client dictionaries (77 `LocaleNamespaceMap` namespaces typed against `LocaleDictOf<N>` plus `directory-browser`). For built-in plugin titles/descriptions, official on-demand bundle cards, and built-in approval prompts flowing through `LocaleRuntime.resolveText(text)` (following [locale-owned client UI copy](2026-08-23-locale-owned-client-ui-copy.md)), `LocaleRuntime` resolves an explicit `text.ru` field first (honoring `packages/strata/*/locale/ru.json` and third-party plugins shipping `locale/ru.json`), then consults the 524-entry `ruPluginMetadataCatalog` registered via `ctx.locale.registerTextCatalog` (covering `@strata/product-bundle/workspace-scaffold` and plain-string `@deepseek-ai/*`, `@strata/*`, and `cordis:*` built-in plugin metadata lacking `locale/en.json`, wrapped by `PluginInventorySettingsTab` and `ui-plugin-manager` while preserving user literal strings verbatim), and otherwise preserves external strings via `text.en`.
3. **Standard `Intl.PluralRules` interpolation without upstream key churn:** `LocaleRuntime.translate` evaluates ICU-style plural clauses (`{count, plural, one {# ...} few {# ...} many {# ...} other {# ...}}`) using `Intl.PluralRules` for the matched dictionary entry's locale (`hit?.locale ?? activeLocale`, degrading to English plural rules for synthetic BCP 47-style tags) while keeping `{param}` substitution unchanged, formatting Russian counters (`1 файл`, `2 файла`, `5 файлов`) with zero external npm dependencies and zero key changes in upstream client packages.
4. **Electron shell, Windows NSIS installer geometry, early boot page, and Strata role presets:** `apps/desktop/src/locale.ts` provides a complete 191-key typed `ru` dictionary and defaults `resolveDesktopStartupLocale` and early pre-Host fatal dialogs to `'ru'` when `preference` is null, normalizing regional subtags (`ru-RU`, `en-US`, `zh-CN`) and falling back cleanly on unknown tags without mutating stored preferences. Inside the `600`-pixel Windows NSIS installer dialog (`apps/desktop/installer/pages.nsh`, `apps/desktop/installer/theme.nsh`, and `apps/desktop/installer/locales/ru_RU.json`), `$InstallerChoose` is widened to `240` px centered at `X = 180` and `INSTALLER_BUTTON_WIDTH` / `INSTALLER_BUTTON_X` are set to `200` / `200` so Russian captions (`"Выберите местоположение"`, `"Установить сейчас"`) render without clipping. `packages/client/web/src/boot-page.ts` renders `STRATA HARNESS` with Russian default boot status copy. `packages/preset/agent-preset-registry/src/display.ts` and `ui-agent-preset` recognize the active four-preset lineup (`standard` default, `strata-developer`, `strata-analyst`, `strata-designer`, while retaining copy for disabled `ptc`, `cordis`, and `minimal` plus `strata -> strata-developer` legacy lookup aliasing via `AgentPresetRegistry.Config.aliases` and fallback `presetStrata*` display keys) with localized `ru`/`en`/`zh` descriptions, the compact Russian `'По умолчанию'` `inUse` badge, and wrapping preset card headers while preserving role names and English model-facing prompts.

## Alternatives considered

**Add `'ru'` to `LOCALE_IDS` (`BuiltInLocaleId`) and edit every upstream package directly.** Touching more than fifty `packages/client/*/locales.ts` modules and adding over two hundred `packages/*/*/locale/ru.json` files creates a broad conflict footprint on every `dsh-v*` upstream synchronization, whereas `@strata/locale-ru` provides compile-time `LocaleDictOf<N>` key verification and runtime parity checking inside one isolated `@strata/*` package.

**Replace `FALLBACK_LOCALE = 'en'` globally with `'ru'`.** `FALLBACK_LOCALE` serves as the terminal dictionary lookup language for third-party plugins without Russian dictionaries (`assertFallbackChain` requires every language's fallback chain to terminate at `FALLBACK_LOCALE`) and as the baseline expectation of standalone upstream unit tests; separating deployment-configured `defaultLocale` from `FALLBACK_LOCALE` satisfies both obligations.

**Load `@strata/locale-ru` in the normal second client boot batch or fetch Russian dictionaries lazily.** `@deepseek-ai/dsh-client-locale` runs with `immediately: true`; delaying `@strata/locale-ru` to phase two mounts initial chrome and notifies Electron's `__DSH_LOCALE__` bridge in `'en'` before switching to `'ru'`, causing visible menu and UI flicker.

**Rewrite upstream counter keys into multi-key plural sets or add an external ICU parser package.** Renaming keys across upstream client packages breaks Soft-Fork isolation, and adding an external dependency is unnecessary when platform `Intl.PluralRules` handles plural selection in a small, self-contained formatter.

## Consequences

- `@strata/locale-ru` activates in client Boot Phase 1 (`immediately: true`), participates in `strata-product.json` version synchronization (`pnpm run strata:version`) and `pnpm run strata:audit-overrides` (`scripts/strata/fork-ops.ts`), and opens fresh Web and Desktop profiles in `'ru'` with selector order `['Русский', 'English', '中文']`.
- `scripts/strata/russian-localization-parity.spec.ts` enforces 100% `ru` key and placeholder parity across all 78 client dictionaries, all 191 Electron shell keys in `apps/desktop/src/locale.ts`, and every built-in plugin `locale/en.json`, plain-string built-in YAML plugin specifier, and `OFFICIAL_ON_DEMAND_CATALOG` metadata entry, failing deterministically when an upstream `dsh-v*` merge introduces untranslated copy.
- Regional subtags (`ru-RU`, `en-US`, `zh-CN`), unknown preference tags, and manual disabling of `@strata/locale-ru` fall back cleanly without throwing, exposing raw keys, or overwriting stored `locale.preference`, while standalone upstream `packages/client/*` unit suites pass unmodified and `LocaleRuntime.translate` formats Russian `one` / `few` / `many` plural branches via `Intl.PluralRules('ru')`.

When an upstream `dsh-v*` release renames a `LocaleNamespaceMap` key or edits an English `locale/en.json` description, TypeScript compilation of `@strata/locale-ru` (`LocaleDictOf<N>`) and `scripts/strata/russian-localization-parity.spec.ts` fail on the `sync/dsh-v*` branch until `@strata/locale-ru` or `apps/desktop/src/locale.ts` is updated, preventing silent English fallback regressions in shipped StrataHarness releases. Russian UI strings are typically 25–35% longer than English equivalents, so narrow settings pills, sidebar items, headers, and Windows NSIS installer controls (`apps/desktop/tests/installer-locales.spec.ts`) require concise engineering phrasing and layout verification.
