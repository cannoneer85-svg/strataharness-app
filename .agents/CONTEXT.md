# Глоссарий проекта

Единый источник терминов процесса разработки StrataHarness, предметной области DeepSeek Harness и стека технологий. Используется агентами во всех задачах.

## Стек технологий

- **Язык и среда:** TypeScript 6 (`strict: true`, ESM `"type": "module"`), Node.js `^22.19.0 || >=24.0.0`, Python (SDK/runtime), Rust/C++ native addon (`native/system`).
- **Фреймворк и архитектура:** вендорированный Cordis (`@deepseek-ai/cordis`), монорепозиторий `pnpm` workspaces (`packages/<group>/<pkg>/`, `apps/*`, `website`), React 18 + Vite 8 (Web/Desktop GUI), VitePress (сайт документации).
- **Хранилище и персистентность:** версионированный журнал сессий JSONL/SQLite (`SESSION_FORMAT_VERSION`, монотонный `SCHEMA_VERSION`, смежные миграции без перезаписи выпущенных поколений).
- **Тестирование и гейты:** Vitest 4 (`test`, `test:coverage` 100% на `packages/*/*/src`, `test:snapshot`, `test:e2e`, `test:expected`), Oxlint + `tsgolint`, `tsdown`, `jscpd`, `publint`, Lefthook (`lefthook.yml`) и оркестратор гейтов `scripts/run-gates.ts` (`doc-sync`, `test:docs`, `hygiene`).

## Термины процесса (StrataHarness)

### Маршрутизация задач

**Шаг 0**:
Определение Типа задачи и Категории до начала любой работы. Агент предлагает в первом ответе, пользователь подтверждает на стоп-гейте.
_Avoid_: триаж (это отдельный процесс для входящих issue)

**Тип задачи**:
`Development` (меняет код, конфигурацию, тесты или скрипты) или `Analysis` (исследование, аудит, сравнение с документом в `docs/analysis/` без изменения кода).

**Категория**:
Оценка масштаба задачи `Development`: `Minor`, `Feature`, `Epic` или `Fog (Туман)`. Задаёт обязательные темы раундов интервью и маршрут по этапам.
_Avoid_: сложность, T-shirt size

**Туман (Fog)**:
Состояние задачи, при котором путь к результату не виден и не укладывается в одну сессию. Ведёт в `/wayfinder` вместо обычного интервью.

### Этапы и управление контекстом

**Цикл разработки**:
Шестиэтапный путь задачи `Development`: 1. Интервью (`grill-with-docs` / `wayfinder`) → 2. Спецификация (`to-spec`) → 3. Тикеты (`to-tickets`) → 4. Реализация (`implement`) → 5. Ревью (`code-review`) → 6. Закрытие (`close-task`).

**Стоп-гейт**:
Обязательная остановка в конце Шага 0 и каждого этапа: полный текстовый отчёт с нумерованными опциями продолжения плюс одновременный вызов `ask_question`. Переход дальше — только после явного подтверждения пользователя.

**Handoff**:
Перенос контекста между сессиями без коммита: документ в `docs/handoff/YYYY-MM-DD-<feature>.md`, обновление `docs/handoff/LATEST.md`, очистка завершённых файлов из `.scratch/<feature>/`.
_Avoid_: закрытие задачи

**Close-task**:
Полное закрытие задачи строго по команде пользователя: preflight-проверки, шаги Handoff, очистка `.scratch/<feature>/` и один локальный conventional-коммит без `git push`.
_Avoid_: handoff, ship, finish

**Оркестратор**:
Главный агент в стратегии последовательных субагентов (`Sequential Subagents`). Формирует Бриф, выдаёт тикеты субагентам-исполнителям по одному и верифицирует результат; сам продуктовый код не пишет.

**Бриф**:
Самодостаточный промпт (`.scratch/<feature>/BRIEF.md`), с которым запускается изолированный субагент-исполнитель.

**minimal-diff**:
Дисциплина контроля объёма решения: лестница выбора реализации из 7 ступеней, приоритет чистоты кодовой базы над размером разового патча, отказ от спекулятивных абстракций.

**Запретные зоны**:
Критические области (безопасность, песочница, авторизация, валидация внешних границ, обработка ошибок, совместимость форматов сессий и тесты поведения), где запрещено упрощать реализацию ради краткости.

**Adversary**:
Независимый субагент-скептик на этапе `code-review`, атакующий diff с презумпцией сбоя (гонки, обход границ безопасности, утечки ресурсов и потеря данных).

## Термины предметной области (DeepSeek Harness)

**Capability seam**:
Полная связка из трёх ролей: Service Definition (контракт), Service Provider (реализация) и Consumer (потребитель).

**Agent Note**:
Архитектурная запись решения в `.agents/notes/{proposed,implemented,rejected,archived}/` (единый дом архитектурных решений репозитория вместо отдельного `docs/adr/`).

**Source plane vs Artifact plane**:
Разделение исходников (`src/`, резолв через `tsconfig` `paths` на чистом дереве) и собранных артефактов (`lib/`, `build:artifacts` + `build:check`), которые никогда не смешиваются.

## Термины дистрибуции и сопровождения форка (StrataHarness Desktop)

**Soft-Fork**:
Управляемый форк монорепозитория `deepseek-ai/deepseek-harness`, в котором продуктовые пакеты, CI-воркфлоу и скрипты сопровождения изолированы в пространствах `packages/strata/*`, `scripts/strata/*`, `.github/workflows/strata-*.yml` и `resources/strataharness`, а синхронизация с оригиналом выполняется только по релизным тегам `dsh-v*`.
_Avoid_: Hard-Fork, вендоринг

**`strata(override)`**:
Маркированный conventional-коммит точечной врезки в файл апстрима, обязательный для учёта и автоматического аудита расхождений при слиянии новых тегов `dsh-v*`.
_Avoid_: немаркированный патч ядра

**Релизный тег продукта (`strata-v*`)**:
Тег выпуска десктоп-дистрибутива StrataHarness вида `strata-v<version>`, отделённый от тегов апстрима `dsh-v*` и инициирующий сборку и публикацию релиза.
_Avoid_: `dsh-v*` (резерв за релизами апстрима)

**Канал автообновления (`DOWNLOAD_PROD_ORIGIN`)**:
Статический HTTPS-источник метаданных `electron-updater` (`strataharness/feeds/<target>/latest*.yml` и подписанных артефактов), полностью изолированный от инфраструктуры DeepSeek и Tencent COS.
_Avoid_: CDN DeepSeek, Tencent COS

**Двухконтурное версионирование (`strata-product.json`)**:
Разделение продуктовой SemVer-версии `StrataHarness` (`1.0.0` → `1.1.0` → `1.1.1` для установщиков, `app.getVersion()`, UI, тегов `strata-v*` и автообновления) и версии базового движка `@deepseek-ai/dsh-*` (`upstreamBaseTag`), предотвращающее конфликты слияния в манифестах апстрима.
_Avoid_: перезапись версии в пакетах `@deepseek-ai/dsh-*`

**Радар апстрима (`strata-upstream-watch`)**:
Механизм фонового и CLI-мониторинга новых релизных тегов `dsh-v*` для системного архитектора (вне клиентского приложения), формирующий Impact-отчёт по карточкам `docs/upgrade-guide/` и затронутым файлам `strata(override)`.
_Avoid_: клиентская проверка обновлений

**Языковой пакет продукта (`@strata/locale-ru`)**:
Изолированный в `Soft-Fork` пакет русской локализации интерфейса и метаданных встроенных плагинов `StrataHarness`, устанавливающий русский язык первым и активным по умолчанию (`Русский` → `English` → `中文`) без распыления словарей по апстрим-пакетам.
_Avoid_: правка словарей напрямую в апстрим-пакетах `@deepseek-ai/dsh-*`
